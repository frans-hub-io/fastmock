# FastMock UI

The web UI of FastMock: a React single-page app that the `fastmock` binary embeds and serves at `/ui` on the
admin listener. User documentation is in [`docs/guide/ui.md`](../docs/guide/ui.md); this file is for developers.

Stack: Vite, React 19, TypeScript (strict, `noUncheckedIndexedAccess`), React Router, TanStack Query, Mantine
(CSS modules, no runtime CSS-in-JS), CodeMirror 6, `openapi-fetch` with types generated by `openapi-typescript`,
`swagger-ui-dist`, ESLint with `typescript-eslint`, Vitest with Testing Library, Playwright.

## Requirements

- Node.js 22 and npm 10.
- Dependencies are pinned to exact versions and locked in `package-lock.json`; always install with `npm ci`.
- `.npmrc` disables install scripts (`ignore-scripts=true`); no dependency needs one.

## Commands

```sh
npm ci                 # install exactly what package-lock.json says
npm run dev            # Vite dev server on http://localhost:5173/ui/
npm run gen:api        # regenerate src/api/schema.d.ts from ../docs/api/openapi.json
npm run lint           # ESLint (type-aware), zero warnings allowed
npm run typecheck      # tsc --noEmit for the app, the tests and the configs
npm test               # Vitest unit and component tests (jsdom)
npm run build          # type-check and build into ui/dist
npm run e2e            # Playwright end-to-end tests against a running fastmock
```

### Development server

`npm run dev` proxies `/__admin`, `/openapi.json`, `/metrics` and `/ui/config.json` to a local fastmock admin
listener on `http://127.0.0.1:25090` (override with `FASTMOCK_ADMIN_URL`). Start one with in-memory storage:

```sh
cargo run -p fastmock-server --bin fastmock -- hash-token --generate   # prints a token and its SHA-256
FASTMOCK_STORAGE=memory \
FASTMOCK_LISTEN=127.0.0.1:25080 FASTMOCK_ADMIN_LISTEN=127.0.0.1:25090 \
FASTMOCK_ADMIN_TOKENS="dev:admin:<sha256>" \
cargo run -p fastmock-server --bin fastmock -- serve
```

Then open `http://localhost:5173/ui/` and paste the token. The dev server does not send the CSP of the embedded
UI; check CSP-sensitive changes against a real `fastmock` (see below).

### API types

`src/api/schema.d.ts` is generated from the admin OpenAPI document (`docs/api/openapi.json`, written by the server
tests) and committed, so building the UI never needs the Rust toolchain. After an admin API change run
`npm run gen:api` and commit the result. Requests go through the typed `openapi-fetch` client in
`src/api/client.ts`; only raw uploads (files, gRPC descriptor sets, auto-detected imports) use `src/api/http.ts`.

Screens for optional server features (files, services, contract tests, async mocks, settings, snapshots) check
`/openapi.json` and show "not available on this server" when the server does not offer the endpoint.

### Embedding

`npm run build` writes `ui/dist`. `crates/fastmock-server/src/ui.rs` embeds that directory into the binary with
`rust-embed` at compile time; `cargo build` after `npm run build` picks up the new files (the crate's `build.rs`
watches `ui/dist`). Without `ui/dist` the server still builds and `/ui` explains that the UI was not built. The
Docker image builds the UI in a Node stage first.

The server serves hashed files under `/ui/assets/` with `Cache-Control: public, max-age=31536000, immutable`,
`index.html` with `no-cache`, and every other `/ui/...` path that is not a file as `index.html` (client-side
routes). `index.html` carries a per-response style nonce in `<meta name="fastmock-style-nonce">` that matches the
`style-src` of its Content-Security-Policy; `src/lib/nonce.ts` hands it to Mantine, CodeMirror and the scroll lock
of modals. Scripts are only ever loaded from `'self'`: never add inline scripts, `eval`, `new Function` or HTML
rendering of server data (`dangerouslySetInnerHTML` is rejected by the lint configuration).

## Tests

`npm test` runs the Vitest suites in `src/**/*.test.ts(x)`: the JSON-schema validator and CodeMirror completion,
helpers (curl, diff, matchers, import detection) and component tests of login, role handling and the stubs list
with a mocked `fetch`.

`npm run e2e` drives Chromium against a running fastmock with the UI embedded:

```sh
export FASTMOCK_E2E_URL=http://127.0.0.1:25090          # admin listener (default)
export FASTMOCK_E2E_DATA_URL=http://127.0.0.1:25080     # data plane (default)
export FASTMOCK_E2E_ADMIN_TOKEN=<admin token>
export FASTMOCK_E2E_VIEWER_TOKEN=<viewer token>
npx playwright install chromium                          # once
npm run e2e
```

The suites cover login and logout, creating, editing, calling and deleting a stub, finding the call in the
journal, verification, the viewer role, and Swagger UI executing an authorized call. They fail on any
Content-Security-Policy violation reported by the browser. Without the two tokens the suites are skipped.
